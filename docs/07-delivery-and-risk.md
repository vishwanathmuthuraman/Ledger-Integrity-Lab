# 07 — Technical limitations and validity threats

This repository defines a proposed accounting-review experiment. It contains no measured detection results and provides no audit opinion or finding of wrongdoing.

## What the current artifacts establish

The original synthetic scenarios specify intended behavior for exact amounts, information availability, coverage, scope and neutral review states. Documentation validation checks those authored contracts and selected fixture invariants. It does not establish application correctness, ranking quality or real-world generalization.

## Threats to valid conclusions

| Limitation | Consequence | Required evidence or control |
|---|---|---|
| Anomaly interpreted as guilt | An unusual entry may have a legitimate explanation | Neutral states, traceable evidence and qualified human findings |
| Synthetic shortcut learning | A model may learn generator artifacts instead of accounting patterns | Independently authored templates, nuisance matching and label-like identifier tests |
| Future information leakage | Later reversals or findings can inflate historical scores | Availability cutoffs for records and labels; frozen experiment manifests |
| Unresolved labels treated as routine | Selective investigation can distort precision and recall | Explicit unresolved labels, coverage and lower-bound reporting |
| Incomplete ledger coverage | Missing feeds can resemble absent support or counterpart entries | Completeness diagnostics and abstention where scope is insufficient |
| Legitimate closing activity | Recurring adjustments may dominate the review queue | Hard negatives and policy-aware review questions |
| Balanced entries mistaken for truthful accounts | Correct arithmetic does not establish business substance | Separate integrity validation from review concerns |
| Unauthorized linked evidence | Cross-organization or out-of-engagement references can expose records | Scoped joins, canary tests and export checks |
| Unsupported explanations | Fluent output can imply causes that source records cannot establish | Deterministic operands, source citations and perturbation checks |
| Correlated review cases | Reversals and repeated entries can double count one issue | Case grouping with separate member-level workload diagnostics |
| Dataset reuse rights unresolved | Availability of a download does not establish redistribution permission | Versioned provenance, license review and separate intake evidence |
| Runtime claims unmeasured | Estimated throughput or memory cannot substantiate performance | Recorded hardware, inputs and retained measured artifacts |
| Policy or calendar drift | Applicable controls can differ across entities and dates | Versioned policy and calendar evidence selected as of the observation time |
| Standards overinterpreted | Research analytics do not confer professional assurance | Scoped claims and qualified applicability review |

## Interpretation limits

A positive result on synthetic data supports further evaluation under the declared conditions. It does not establish real fraud detection, prevalence, financial savings or audit assurance. A null or negative result should be reported with the same provenance as a positive result.

The [evaluation protocol](04-evaluation.md) defines the comparisons and reporting required for a research claim. The [publication boundary](08-publication.md) distinguishes reproducible public artifacts from restricted records and operational material.
